This link can't be clicked
The white bar along the bottom is painted on top of the course index, so the last item is hidden behind it and clicks don't reach it. On a long course the final sections can't be opened at all. Try clicking this row.
Why it happens
Both the course index and block drawer are cut off. A recent change moved both drawers behind the footer bar. The bar stretches the full width of the window, so wherever it overlaps a drawer, that part of the drawer disappears.

This only happens on pages with a narrow content column. Set Page type to Full width and the problem goes away, because there the drawers still sit in front of the bar.
Step 1: the bar becomes invisible
The full-width bar stops being painted and stops catching clicks. It's now just an invisible frame, so clicks pass straight through to the drawers underneath — the row in the course index is reachable again.
Step 2: only this panel is painted
Only the footer area that matches the page content width has a white background and horizontal line. That's the entire fix — the footer no longer reaches the drawers, so it can't cover them.
Proposed footer matches this container's width
This content area is what the user is navigating between. Sidebars are complementary nav. The fix works by making the footer line up with the main content area's left and right edges.
Full-width pages do change — slightly
Yes, these pages change too, even though they never had the bug. The change is small: the white bar's left and right edges move inward by about 48px.

Nothing else moves — every button stays exactly where it is. That 48px is the only thing needing a design decision.
The fix breaks this bar
This bar has lost its white background and top line — that's the bug, not unfinished styling.

It's built by JavaScript, which throws away the inner panel the fix puts the background on. So there's nothing left to paint. It's fixable in one line, by painting whatever the footer contains rather than one specific panel.
Only two screens are affected
Just assign grading and gradebook setup use this bar. Both are full-width pages, which never had the original bug — so limiting the fix to the page types that did have it would make this breakage disappear on its own.

Course bulk edit is built differently and is not affected. Switch to it to see it keep its background.
The readout checks itself
It compares the footer panel's edges against the content area's edges every time anything changes, and says whether they match. So you can test every screen size by resizing the window, rather than measuring by hand.
Demo controls only
Not part of the proposal. Use it to flip between today's behaviour and the fix, and between the page types. Options that can't show the problem are greyed out, with a note saying why.
